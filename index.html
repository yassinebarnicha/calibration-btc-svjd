Hands-on calibration

Deribit BTC, snapshot 17:00 UTC, index · full chain of options over maturities · model ( parameters) · pricer · the tabs choose what is shown to the right of the smiles. Default data = production book.
After each date: the number of historical calibrations available that day (in "Starting point", under the calibrated model), of your saved settings, and "downloaded" for a day fetched with "Today" (kept in this browser and in the application's jours/ folder).
Parameters specific to each day
Stacks N consecutive days from the chosen day. The same contract seen on two consecutive days gives two distinct maturities in T (T, then T − 1/365): N days multiply by N the points of the term structure, with no new data to collect. The model parameters are shared by all stacked days — v₀ included, which only holds for close days.

Export parameter sets (JSON)
Format "calibration-a-la-main/jeux": model, parameters, origin, maturities, pricer, loss and results of each set. Written to resultats/ if a folder is chosen, otherwise downloaded.
A setting keeps everything: model, parameters, day, maturities, target, filters, pricer, loss, bounds and results. It comes back in "Starting point" for the same model when you return to that day. It is written to disk at once (on the first save, choose the application folder: the browser remembers it) in resultats/<day>/<model>/NN_name/, and appended to resultats/jeux_enregistres.json (reglage.json, results.csv, df_used.csv, smiles.png); "final" copies the chosen setting to <day>/final/. Delete only removes the browser copy, never the folders.
1 · Maturities
Production = the last 6 maturities beyond 10 days, minus 27/12/2024. The counter gives the options that pass the other filters.
2 · Target and filters
Left empty, these filters apply to every maturity. A threshold switches them off on shorter maturities: at one week an option at 0.004 BTC is a normal wing price, at one year it is an illiquid tail whose mark means nothing.
Empty field = no filter. Relative spread = (ask−bid)/mid; the target IVs are our own Black-76 inversions.
3 · Pricer
COS (default): N = 512, L = 24; the fastest (about 3 times PROJ), needs a valid second cumulant. PROJ: N = 2¹¹, L = 20; one FFT per maturity, more robust when |μJ|, σJ or λ are large. Both pricers work for every composition of the model.
Price your own options
With the active model and its current parameters (those of the day shown), priced with PROJ (N = 2¹¹, L = 20: accurate even for very short maturities and far strikes).
CSV file
One row per option. Required columns: type (call/put, C/P), K, F, and the maturity as T (years) or jours (days) or echeance (YYYY-MM-DD, Deribit expiry at 08:00 UTC, counted from valorisation if that column exists, otherwise from the snapshot of the day shown). Optional: r (0 otherwise), prix_marche (market price, $); any other column is copied as is. Separator "," or ";" (with ";", the decimal comma is accepted). The returned file is the same, plus: iv_marche, prix_modele, iv_modele, ecart_iv_bps, ecart_prix, delta_modele, gamma_modele, vega_modele, theta_modele, delta_b76, gamma_b76, vega_b76, theta_b76, vol_b76, modele, pricer, erreur. Units: Δ per $ of F, Γ per $², Vega per 1.00 of vol (÷ 100 for one point), Θ in $ per day; Black-76 at the market IV if the price is given, otherwise at the model IV.
Example of an expected file (comma separator, decimal point):
id,type,K,F,jours,r,prix_marche
put-70k,put,70000,83757,30,0.06,1245.5
call-95k,call,95000,83757,30,0.06,980
atm-90j,call,84000,83757,90,0.06,
date,put,80000,83757,,0.06,
The last row of the example would give an error: without T, jours or echeance, the maturity is missing. With an echeance column instead of jours: 2026-12-25. French Excel version: separator ";" and decimal comma, for example put-70k;put;70000;83757;30;0,06;1245,5.
Exotic options (Monte Carlo)
Future paths simulated with the active model. Nothing is computed before the click.
Variables: FT (F at expiry), MOY (average), MAX, MIN (over the steps), F0, K, B, B2, Q, T (years). Functions: max, min, abs, exp, log, sqrt. A comparison is worth 1 or 0: (MAX < B) * max(MOY - K, 0) is an up-and-out Asian; Q * (FT > K) * (MIN > B2), a digital with a lower barrier. Paid at expiry, discounted at r.
Average, extrema and barriers are read at every step (discrete monitoring: 1 step per day ≈ daily fixing). American: exercise possible at every step, continuation value estimated by regression (Longstaff-Schwartz 2001, basis 1, x, x², x³ with x = F/K, in-the-money paths only); an "out" barrier knocks the option out, an "in" barrier is not supported for American exercise. Schemes: CIR factors by QE (Andersen 2008), Merton, bi-lognormal, Kou, Variance Gamma and NIG jumps, compensated (the future stays a martingale); CGMY has no simple exact simulation. Control: the European with strike K is simulated on the same paths and compared with its Fourier price (PROJ); the gap measures the simulation bias, and it serves as a control variate.

The full dynamics of the active model is shown by the "ⓘ Dynamics" button of the Model tab. The JavaScript pricers are checked against those of the Python project (gap < 3e-6 $). Data preparation identical to the production book: mark target if bid ≤ mark ≤ ask, else mid; bid > 0 and ask > 0; relative spread < threshold; target price in BTC > threshold; out-of-the-money options; Black-76 vega at the target IV; weights 1/vega² with a 1e-4 floor. With the default values the production book is recovered exactly. The IV and price RMSE do not depend on the loss chosen.

4b · Parameter boundswide
The bounds limit the sliders, the input fields and the optimiser. Parameters on a log scale (κ, θ, σ, v₀, dispersions, scales) must stay > 0; |ρ| < 1; intensities λ ≥ 0. "Production" = the production bounds of the active model. A value outside the new bounds is brought back inside.

6 · Optimiser
DE settings
Search in slider space, within the current bounds; locked parameters stay fixed. Initial population by Latin hypercube. Stops when std(losses) ≤ atol + tol·|mean| over the population, or at the generation cap. scipy defaults: best1bin, mutation 0.5–1.0, recombination 0.7, tol 0.01. Production: rand1bin, 0.7–1.5, 0.6, tol 1e-7, atol 1e-8, popsize 25. Same seed, same settings, same data → same result. Cost: popsize × free evaluations per generation (≈ 0.2 s with COS, ≈ 0.7 s with PROJ for 8 free parameters).
Local settings (Nelder–Mead)
Stops when (f_max − f_min)/f_min over the simplex ≤ tolerance, or at the evaluation cap. Initial step in slider units (0–1). Nelder–Mead is local: starting from a good point (saved setting, the day's Bates calibration converted) matters more than the number of evaluations.
Move a slider: everything is recomputed live.
